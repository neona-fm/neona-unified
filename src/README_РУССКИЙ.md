# Neona Split VPN 1.5 — Windows 10/11 x64

## Что изменилось после проверки PowerShell (`loc=RU`)

**Критерий работы VPN:** зарубежные сайты открываются, российские сайты открываются, а самостоятельный системный HTTPS-запрос без прокси имеет **не российский** внешний IP. Запуск Xray и доступность сайтов не считаются успешным VPN.

В версии 1.4 предварительная проверка могла завершиться успешно по ответу `generate_204`, не узнав выходной IP сервера; подтверждение кнопкой было ручным. Версия 1.5 исправляет этот недостаток, отдельно проверяет системный IP и показывает страну.

### Попытка устранить конфликт маршрутов Windows

В TUN Xray вместо единственного маршрута `0.0.0.0/0` установлены два более конкретных: `0.0.0.0/1` и `128.0.0.0/1`, а для IPv6 — `::/1` и `8000::/1`. Это позволяет переиграть конкурирующий системный маршрут по длине префикса (когда другой VPN/адаптер также имеет `0.0.0.0/0`). При этом Xray автоматически добавляет и снимает **только собственные** маршруты на время работы; принудительного `route delete` и сетевого сброса нет. Это техническая гипотеза для конкретного ноутбука, пока не подтверждённая живой проверкой.

### Проверка состояния

1. До включения TUN Xray тестирует локальный прокси и **обязательно получает его внешний IP** через Cloudflare / ipinfo / ipify. Если узнать IP не удалось, TUN не включается.
2. После старта TUN Windows-маршруты записываются в `%APPDATA%\NeonaSplitVPN\routes.log`.
3. Программа самостоятельно запрашивает Cloudflare/ipinfo/ipify через **прямой HTTP-клиент без системных прокси**, с предпочтением IPv4, и сверяет внешний IP с результатом до TUN. Также проверяет `ya.ru`.
4. Если страна определена как `RU`, TUN автоматически останавливается, а приложение показывает причину и сохраняет `routes.log`.
5. Надпись `Проверено` появляется только после измерения внешнего системного IP и проверки российского сайта. Кнопка `Проверить системный IP` повторяет эту реальную проверку.
6. Автоматический откат через 90 секунд оставлен на случаи неопределённого состояния.

### Установка

1. Закрой прежний `NeonaSplitVPN.exe` 1.4.
2. Распакуй этот ZIP в отдельную папку и запусти `NeonaSplitVPN.exe`.
3. Подписка и ранее установленный Xray-core 26.10.31 сохраняются в `%APPDATA%\NeonaSplitVPN` и должны быть подхвачены. Новый ключ вводить не требуется.
4. Перед проверкой выключи прежние Hiddify/Xray-клиенты, включая их прокси/TUN, но не удаляй: они остаются вариантом отката.
5. Нажми `Подключить`, дождись проверки. В приложении должны появиться IP и страна. При отказе приложи `routes.log` и последний `engine.log` (не присылай `profile.dpapi` и `active.json` — в них секреты).

**Важно:** Windows EXE кросс-собран, синтаксис и проверки протестированы автоматически. Реальный TUN на ноутбуке ещё не испытан; успешное изменение маршрута не гарантируется. Если Windows сохраняет более конкретные маршруты других программ или VPN-сервер недоступен, понадобится дальнейшая точечная правка по логу. Проверять изменение геолокации служб Windows, GPS/Wi-Fi Location API — отдельная задача, это приложение меняет только внешний сетевой IP.
